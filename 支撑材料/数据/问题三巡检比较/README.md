# Q3 巡检点数比较

固定论文采用的 M020，仅改变环上巡检点数与半径：1+6、1+7、1+8 分别采用 1125、998、940 米。`1` 表示共同的原点测站。三者保留相同的定位、光学决策、扫点替代与终止机制，不改变正式采用参数。

## 运行

完整解压支撑材料后，在包根目录运行：

```text
python -s -B -X utf8 问题三_七八九点巡检对比.py --output 运行结果/巡检布局比较 --workers 3
```

验证环境与论文主体一致：Python 3.9.13 及支撑材料的 `环境依赖.txt`。也可用 `--support 支撑材料根目录` 显式指定包的位置。全程离线，252 次运行通常需数分钟；输出目录必须尚不存在。

## 文件与口径

- `问题三_七八九点巡检对比.py`：比较、独立审计和统计入口，调用支撑材料中的冻结求解程序。
- `frozen_inputs.json`：既有确认组的全部 84 个 Q3 场景、正式 M020 参数和原六环结果，用于检查重跑一致性。每个源数 10–16 各有 12 场。它们是复用场景，不能计为新增独立确认样本。
- `results/protocol.json`：运行前登记的参数、版本与比较范围。
- `results/rows.json`、`summary.json`、`paired.json`、`strata.json`：逐场费用、总表、与六环的配对差值和源数分层结果。
- `results/baseline_agreement.json`、`integrity.json`：原六环数值逐字段匹配与运行完整性。复算还生成 `archive_agreement.json`，核对全部 252 次存档的费用、动作数和全清结果；最后以新输出目录 `integrity.json` 的 `passed: true` 为通过标准。
- `results/runs/`：复算时自动产生的逐动作记录、解与独立审计；每个场景保存三种布局。

总指标先算每场完整模拟费用/清除源数，再对 84 场等权平均。费用分项也先按每场源数归一后等权平均。所有场景均须全清并通过审计；不得剔除不利或失败场景。待扫频道随搜索和清除变化，因此固定路线长度只能解释移动与检测的取舍，不能替代整场费用。

## 连续覆盖与几何含义

原点覆盖半径 1000 米内；环点覆盖剩余圆环。令环点数为 n、半径为 R、α=π/n，对外环源的径向距离 ρ∈[1000,1800]，最近环点与其角差不超过 α。距离平方对 ρ 是凸函数，故只需检验两端：

`D²(n,R)=max{1000²+R²−2000R cosα, 1800²+R²−3600R cosα}≤1000²`。

三组参数的最大距离分别约 999.110662、999.501401、998.594844 米；坐标舍入到毫米引入的位移不超过 0.000708 米，仍有充分接收余量。这给出连续区域证明，不能用有限采样没有漏点替代。

对于理想等角环点，从原点出发且不必返回的最短固定访问路线为 `L=R+2(n−1)Rsin(π/n)`：第一段至少 R，其余段至少为相邻弦长，顺次访问恰达到下界。这不包含清除与定位绕行，也不意味着该布局是整场最优。点数增多虽可缩短固定路线，却增加检测机会；实际选型应依据整场同场对照。

本比较仅覆盖三种预先指定的等角单环布局，不证明任意点集或整场任务的全局最优；合成场景分布不代表官方分布。
